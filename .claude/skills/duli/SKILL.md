# 둘이검토 (duli)

**사용자가 보는 것은 셋뿐이다.** 내 AI(담당 AI), 담당 AI가 부르는 검토 AI, 그리고 둘이 파일을 주고받는 공유 폴더. 사용자는 담당 AI 하나에게 "검토해"라고만 한다. 나머지는 담당 AI가 한다.

```
나 ──"검토해"──▶ 담당 AI ──파일──▶ 공유 폴더 ◀──파일── 검토 AI
                    ▲                                     │
                    └────── "틀린 것 3개, 반영 2개" ◀────────┘
```

이 스킬을 실행하는 AI가 **담당 AI**다. 검토 AI는 다른 회사 AI(클로드 ↔ GPT)이거나, 같은 도구의 다른 모델을 새로 띄운 것이다. 담당 AI가 파일을 쓰고, 검토 AI의 답을 받아 하나씩 받아들이거나 근거로 반박하고, 끝을 선언한다. 게시·발송·삭제·배포는 사용자만 한다.

## 사용자에게 보이는 말

- "반장·짝꿍·문·사다리·세션·Monitor" 같은 말은 **쓰지 않는다.** 아래 절의 이름은 담당 AI만 안다.
- 쓰는 말: 담당 AI, 검토 AI, 공유 폴더, 검토 파일, "더 고칠 거 없음".
- 단계를 시작할 때 사람 말로 한 줄만 알린다. "검토 AI(Opus)에게 보냈어요. 3분쯤 걸려요." "답이 왔어요. 지적 5개 중 3개를 반영했어요."
- **끝났을 때 세 줄.** ① 검토 AI가 누구였나 ② 지적 몇 개 중 몇 개 반영, 반영 안 한 것 이유 한 줄 ③ 결과물 경로. 자세한 건 파일에 있다고만 한다.
- **묻는 횟수.** 처음 설정 때 1번(질문 둘). 그 뒤 0번. 사용자만 아는 사실(사업·취향·비용)이 결정의 열쇠일 때만 1번.
- 단계를 todo·task 목록에 올리지 않는다. 검토 AI에게 대화 전체를 넘기지 않고 파일 경로와 질문만 준다.

## 처음 1회 설정 (프로필이 없을 때만)

`~/.duli/profile.json`이 있으면 건너뛴다. "검토 설정 다시"라고 하면 다시 연다. **둘만 한 메시지로** 묻는다.

```
처음이라 두 가지만 여쭐게요.

1. 지금 쓰는 AI 앱은요? (클로드 코드 / 코덱스 앱 / 둘 다 / 챗GPT 웹만 / 제미나이)

2. AI끼리 파일을 주고받을 폴더가 있나요? 원드라이브·구글드라이브처럼 다른 컴퓨터와도 같이 보이는 폴더면 더 좋아요.
   있으면 경로를, 없으면 '없음'이라고 적어 주세요. (없으면 지금 작업 폴더 안에 만들어요)
```

닉네임은 묻지 않는다. 파일의 작성자 표시는 AI 이름(Claude·Codex·Opus·Sol…)이다. 검토 AI의 모델도 묻지 않는다. 아래 "검토 AI 고르기"로 담당 AI가 정하고, 사용자가 "이번엔 ○○로 검토해"라고 하면 그때만 바꾼다.

답을 받으면 **말없이** 한다. 끝나면 만든 것의 경로를 한 번에 보여 준다.

1. **검토 AI 종류를 정한다.** 1번 답으로. 둘 다 → 다른 회사 AI(폴더로 주고받음). 하나 → 같은 도구의 다른 모델을 새로 띄움. 챗GPT 웹만 → 손전달(사용자가 파일을 첨부하고 답을 저장. 담당 AI가 매번 "이 파일을 검토 창에 첨부하고 답을 저장해 주세요" 한 줄로 부탁).
2. **공유 폴더.** 2번에 경로가 있으면 그 안에, 없으면 작업 폴더 안에 `live_collaboration`과 `백업`을 만든다. 이미 있으면 그대로.
3. **규칙 파일.** 작업 폴더의 AGENTS.md·CLAUDE.md에 이미 규칙 파일 경로가 적혀 있으면 그것을 쓴다. 없으면 `templates/협업규칙.md`를 작업 폴더에 `협업규칙.md`로 복사한다.
4. **AGENTS.md·CLAUDE.md.** `templates/AGENTS-블록.md`를 **덧붙인다.** 이미 있으면 덮어쓰지 않고 `.bak`을 남긴 뒤 끝에 `<!-- duli 시작 -->`과 `<!-- duli 끝 -->` 사이로 붙인다. 표시가 이미 있으면 사이만 바꾼다. 없으면 블록만으로 만든다. CLAUDE.md가 없으면 `@AGENTS.md` 한 줄짜리로, 있으면 그 줄이 없을 때만 덧붙인다. 블록의 `<경로>`는 실제 경로로.
5. **프로필 저장.** `{ "tools": "둘 다", "partner_kind": "folder|model|hand", "shared_dir": "...", "rules_file": "...", "partner_model": null, "set_at": "2026-10-09", "skill_version": "2026-10-09.2" }`
6. 검토 AI가 다른 회사 AI면 **검토 AI용 프롬프트**(아래)를 실제 경로를 넣어 코드블록으로 보여 주고 "검토 AI 창에 한 번 붙여 넣어 두면 돼요"라고 한 줄. 다른 모델이면 보여 주지 않는다.
7. 마지막 한 줄: "다음부터는 '검토해'라고만 하면 돼요."

설치 직후 사용자가 이미 할 일을 말했으면(예: "이 설계안 검토해") 설정이 끝나자마자 바로 한다.

## 매번: 시작 전 (말없이)

- 오늘 날짜를 명령으로 확인한다. 프로필을 읽는다. 공유 폴더에 **나에게 온(→ 내 이름) 새 파일**이 있는지 먼저 본다. 있으면 그 일부터.
- 같은 프로젝트의 기존 순번이 있으면 이어 쓴다.
- 새 버전 확인: `https://raw.githubusercontent.com/lifeschedule-dotcom/duli/main/.claude/skills/duli/VERSION`을 읽어 설치본과 비교한다. 4초 안에 안 되면 넘어간다. 새 것이 있으면 한 번만 "새 버전이 있어요. 받을까요?" 받으면 README 설치 명령을 실행하고 "창을 껐다 켜 주세요"로 멈춘다.

### 무엇을 할지 정하기 (사용자에게 설명하지 않는다)

| 사용자 말 | 하는 일 |
|---|---|
| "검토해", "맞는지 봐 줘", "더 나은 방향 없어?" | 대상이 **설계·아이디어**면 설계 검토, **결과물**이면 마무리 검토. 대화와 폴더를 보고 담당 AI가 판단한다. |
| "같이 해", "나눠서 해", "조사해 줘" | 나눠서 하기. 끝나면 자동으로 마무리 검토. |
| 애매하면 | 공유 폴더를 본다. 설계 문서만 있으면 설계 검토, 합친 결과물이 있으면 마무리 검토. 그래도 모르면 그때만 "설계 검토 / 결과물 검토 / 나눠서 하기" 셋 중 고르게 한다. |

### 검토 AI 고르기

- 프로필 `partner_model`이 있으면 그것. 사용자가 "이번엔 ○○로 검토해"라고 하면 그 회차만 그 모델.
- 없으면 **독립성이 높은 순서**로 고르고, 어느 것이었는지 완료 파일과 끝 세 줄에 적는다.
  1. 다른 회사 AI (클로드 ↔ GPT)
  2. 같은 도구의 다른 모델을 새로 띄움. 기준: **지금 쓰는 모델의 한 단계 위, 이미 맨 위면 한 단계 아래.** 지금 도구의 모델 목록(`/model`)에서 고른다. 2026-10-09 예: 클로드 Haiku → Sonnet → Opus → Fable(맨 위면 Opus), 코덱스 Luna → Sol → Astra(맨 위면 Sol). 못 띄우면 한 단계 아래.
  3. 같은 모델, 새 대화창. 대화를 모르니 "먼저 혼자 읽기"는 된다.
  4. 담당 AI 스스로 검토. "검토 안 됨"으로 적는다.
- 새로 띄운 모델에게는 **파일 경로와 질문만** 준다. 답은 똑같이 공유 폴더에 `… → <담당 AI> - 날짜 <모델 이름>.md`로 저장하게 한다. 회차마다 1번, 최대 2회차.

## 공통 뼈대

### 파일 이름

**`<프로젝트> <순번> <할 일> → <받을 AI> - YYYY-MM-DD HHMM <쓴 AI>.md`**
예: `예약 자동화 02 설계안 검토 → Claude - 2026-10-09 1304 Opus.md`

- 순번은 프로젝트 안에서 01부터, 누가 쓰든 이어 쓴다. "→" 대신 "to"도 된다.
- 상대의 파일은 절대 고치지 않는다. 답은 새 파일로. 고쳐 다시 올릴 때는 이전 판을 `백업\… vN.md`로.
- 답 파일에 늘 넣는 것: **한 일 / 증거(경로·근거·출처) / 확인 못 한 것 / 판단이 갈리는 것(선택지 + 추천 + 근거)**. 사실은 **[확인] [2차] [추정] [미확인]**. 사용자·제3자의 감정·의도는 추측해 쓰지 않는다.

### 공유 폴더 지켜보기

| 담당 AI 도구 | 방법 |
|---|---|
| 클로드 코드 | 폴더 지켜보기 도구(Monitor)로 `→ Claude` 새 파일을 알리게 한다. 30분마다 다시 켠다. 폴링하지 않는다. |
| 코덱스 앱·제미나이 CLI | 2분마다 폴더를 한 번 본다. |
| 손전달 | 지켜보지 않는다. 사용자가 "답 저장했어요"라고 하면 읽는다. |

30분 넘게 답이 없으면 사용자에게 한 줄 알린다. 다른 컴퓨터의 검토 AI면 "파일이 그쪽 폴더에 보이는지" 확인을 부탁한다. 검토 AI가 파일을 못 찾으면 **전체 경로를 그대로** 적어 준다. 이름에 화살표가 있어 검색으로는 못 찾는다.

### 검토 AI용 프롬프트 (요청 파일 맨 아래에도 붙인다)

```
너는 검토 AI야. 담당 AI는 <담당 AI>이고, 사용자는 담당 AI와만 대화해.
- 공유 폴더: <공유 폴더 전체 경로>. 2분마다 확인해서 너에게 온(→ <너>) 새 MD 파일을 읽고 일해 줘.
- 답은 같은 이름 규칙의 새 MD 파일로: <프로젝트> <순번> <할 일> → <받을 AI> - 날짜 시간 <너>.md
- 상대의 원본은 고치지 마. 답에는 한 일 / 증거 / 확인 못 한 것 / 판단이 갈리는 것(선택지+추천+근거)을 적어 줘.
- 검토를 요청받으면 담당 AI의 의견을 읽기 전에 결과물부터 먼저 읽고 네 판단을 적어. 그다음 "틀린 것"과 "실제로 안 통할 수 있는 것"을 근거와 함께 적고, 없으면 "더 고칠 거 없음"이라고 분명히 써 줘.
- 사실은 [확인/2차/추정/미확인]을 구분해. 의견이 갈리면 사용자에게 묻지 말고 의견 맞추기 파일에서 근거로 끝내. 새 근거가 없으면 "새 근거 없음"이라고 써.
- 게시·발송·삭제·배포는 하지 마. "완료" 파일이 오면 폴더 확인을 멈춰 줘.
```

## 설계 검토 (아이디어가 완성되기 전)

1. 담당 AI가 대화에서 나온 설계를 **설계안 파일 하나**로 정리한다. 목표 한 줄, 하기로 한 것, 안 하기로 한 것, 전제(사실로 믿는 것), 열린 질문. `<프로젝트> 01 설계안 v1 → <검토 AI>`로 올린다. 담당 AI의 평가·장점은 넣지 않는다(검토 AI가 끌려간다).
2. 묻는 것: **틀린 전제 / 빠진 경우 / 더 단순한 대안 / 이 설계가 실패하는 조건**. 답 형식 "채택 / 더 나은 대안+근거 / 틀림+근거". 끝에 "더 고칠 거 없음" 여부.
3. 답이 오면 항목마다 **반영 / 반영 안 함(이유) / 토론으로**를 정한다. 반영한 것은 v2로 고치고(이전 판 백업) 반영표와 함께 재검토를 요청한다.
4. 끝 조건: 담당 AI의 스스로 검토와 검토 AI의 답이 **둘 다 "더 고칠 거 없음"**. `설계 확정본`으로 저장하고 닫는다. 사용자에게는 세 줄 + "이대로 나눠서 할까요?" 한 줄.

## 나눠서 하기

1. `<프로젝트> NN 작업 분배 → <검토 AI>`에 **배경·목표·현재 상태·완료 기준·결과물 저장 위치·지키는 것**을 다 적는다. 상대가 따로 설명 없이 일할 수 있게. 맨 아래에 검토 AI용 프롬프트.
2. 나눌 기준: **사실 조사·대안 비교·다른 시각은 검토 AI에게, 합치기·최종 판단·기록은 담당 AI가.** 자기 몫은 바로 한다.
3. 돌아오면 **최종본 하나**로 합친다(원본은 백업). 조각으로 끝내지 않는다. 합치면 바로 마무리 검토.

## 마무리 검토 (결과물이 나온 뒤)

1. **담당 AI가 스스로 검토를 먼저 한다.** 틀린 것, 실제로 안 통할 것. 처방마다 "이게 실패하는 상황은?"을 한 줄씩 생각하고 본문에 조건을 붙인다. 고친 목록은 요청 파일 **맨 아래**에 둔다(검토 AI가 결과물을 먼저 읽게).
2. `<프로젝트> NN 검토 요청 → <검토 AI>`: **틀린 것 / 실제로 안 통할 것 / 더 나은 방향 / 공개 전 개인정보·비밀값**. 답 형식 "채택 / 더 나은 대안+근거 / 틀림+근거", 바꿀 문장은 직접 제안하게. 없으면 "더 고칠 거 없음".
3. 답이 오면 **지적마다 표**: 채택 / 반박(근거) / 보류(사용자만 아는 사실) / 토론으로. "검토 AI가 동의했다"는 사실 확인이 아니다. 숫자·기능·정의는 출처로 확인한다.
4. 채택이 있으면 고치고 판을 올려(v2→v3) 재검토. 순번 +1.
5. **끝 조건:** 둘 다 "더 고칠 거 없음"인 회차 한 번. 오타·표현만 남으면 담당 AI가 반영하고 끝으로 본다.

### 의견이 갈릴 때

같은 지적이 두 회차 연속이면 `<프로젝트> NN 토론: <쟁점> → <검토 AI>`를 연다. 쟁점 한 줄, 양쪽 주장, 각 주장이 **틀리는 조건**, 확인할 출처·시험 방법. 검토 AI는 같은 형식으로 답하고 새 근거가 없으면 "새 근거 없음". 담당 AI가 결정하고 이유를 적는다. 기준: 출처로 확인되는 쪽 → 실패 조건이 적은 쪽 → 사용자가 바로 쓸 수 있는 쪽. 쟁점당 2왕복까지, 그래도 안 갈리면 **둘 다 조건을 붙여** 넣는다. 사용자에게는 결과만. 사용자만 아는 사실이 열쇠일 때만 질문 하나.

### 검토가 실패하면 실패라고 쓴다

검토 AI가 답을 안 보냈거나 파일을 못 읽었거나 다른 모델을 못 띄웠으면 그 회차는 **"검토 안 됨"**. 담당 AI 혼자 본 것을 "교차검토 통과"라고 쓰지 않는다.

## 닫기

1. `<프로젝트> NN 완료 → <검토 AI>`: 반영한 것 / 반영하지 않은 것과 이유 / 토론 결정 / 어느 AI·모델이 검토했는지 / 최종 결과물 경로 / **"추가 검토 필요 없음, 폴더 확인을 멈춰도 됨"**.
2. 검토 AI는 완료 파일을 읽으면 멈춘다. 담당 AI도 지켜보기를 멈춘다.
3. 작업 기록 파일이 있는 프로젝트면 한 줄 남긴다. 없으면 완료 파일이 기록이다.
4. 사용자에게 **세 줄**(검토 AI 누구 / 몇 개 중 몇 개 반영 / 결과물 경로). 답장 내용을 나열하지 않는다.

## 요청할 때만

- "검토 설정 다시": 처음 설정을 다시. · "스킬 업데이트해 줘": 새 버전 확인. · "지금 어디까지 왔어?": 이 프로젝트 파일 목록과 누구 차례인지 다섯 줄. · "검토 AI 프롬프트 다시 줘".

## 절대 하지 않는 것

게시·발송·삭제·배포. 상대 AI 파일 고치기. 비밀값·개인정보·대화 전체를 파일에 넣기. 감정·의도 추측. "동의했다"를 사실 확인으로 치기. 검토 안 된 회차를 통과로 쓰기. 담당 AI 의견을 결과물보다 앞에 두기. 사용자에게 의견 차이를 떠넘기기. 사용자에게 내부 용어(반장·짝꿍·문·사다리) 쓰기.
