# 둘이검토 (duli)

AI 하나가 쓴 것은 그 AI가 못 본다. 그래서 다른 AI(또는 다른 모델)가 **먼저 혼자 읽고** 틀린 것·안 통할 것·더 나은 길을 적고, 반장이 하나씩 받아들이거나 근거로 반박해 **"더 고칠 거 없음"**이 양쪽에서 나올 때까지 간다. 이 스킬을 실행하는 AI가 **반장**, 상대가 **짝꿍**이다. 반장이 나누고, 합치고, 토론을 끝내고, 완료를 선언한다. 게시·발송·삭제·배포는 사용자만 한다.

문은 셋이다. 사용자의 일 순서 그대로다.

```
아이디어 ──대화로 설계──▶ ① 설계 검토 ──확정──▶ ② 나눠서 하기 ──합침──▶ ③ 마무리 검토 ──▶ 끝
```

- 사용자에게 보이는 말은 **중학생이 읽어도 되는 말**로 쓴다. 개발자만 쓰는 말은 아래처럼 바꾼다.

| 쓰지 않는 말 | 대신 쓰는 말 |
|---|---|
| 세션, 로그 | 작업 기록 |
| Monitor, 폴링, 워치 | 폴더 지켜보기 |
| 서브에이전트 | 짝꿍(모델 이름) |
| 해시, SHA | 파일 확인값 |
| 커밋, 푸시 | 저장, 올리기 |
| blind pass | 먼저 혼자 읽기 |

- **묻는 횟수.** 처음 설정 1번(질문 여섯 개를 한 메시지에). 그 뒤 회차마다 0번. 사용자만 아는 사실(사업·취향·비용)이 결정의 열쇠일 때만 1번. 어느 문인지 못 알아챌 때만 1번.
- 단계를 시작할 때 사람 말로 한 줄 알린다. "짝꿍에게 보낼 파일을 쓰고 있어요", "짝꿍 답을 기다리고 있어요". 단계를 todo·task 목록에 올리지 않는다.
- **토큰을 아낀다.** 짝꿍에게 대화 전체를 넘기지 않고 파일 경로와 질문만 준다. 반장이 파일을 다시 쓸 때는 바뀐 부분만 고친다. 고치는 회차는 문마다 2번까지, 그다음은 반장이 스스로 검토로 닫는다.

## 처음 1회 설정 (프로필이 없을 때만)

`~/.duli/profile.json`이 있으면 건너뛴다. "프로필 다시 설정"이라고 하면 다시 연다. **여섯 가지를 한 메시지**로 묻는다. 6번의 추천은 2번 답을 모르는 상태라 아래 "혼자 판"의 사다리 규칙으로 일반 추천만 적는다. 아래 문구 그대로 보낸다.

```
처음이라 여섯 가지만 여쭐게요. 번호 옆에 답을 적어 주세요. 모르면 비워도 돼요.

1. 파일에 적을 이름(닉네임)은요? 짝꿍이 "누가 쓴 파일인지" 볼 때 써요.

2. 지금 쓰는 AI 도구는 뭐예요? 쓰는 것을 다 적어 주세요.
   예) 클로드 코드 / 코덱스 앱 / 챗GPT 웹 / 클로드 웹 / 제미나이
   두 개 이상을 같이 쓰면 "같이 쓴다"고 적어 주세요.

3. 컴퓨터는 몇 대예요? (예: 노트북 1대 / 집·회사 2대, 윈도우·맥)

4. AI끼리 파일을 주고받을 폴더가 있나요? 원드라이브·구글드라이브처럼 다른 컴퓨터와도 같이 보이는 폴더면 더 좋아요.
   있으면 경로를, 없으면 '없음'이라고 적어 주세요. (없으면 지금 작업 폴더 안에 만들어 드려요)

5. 이미 쓰고 있는 AI 협업 규칙 파일이 있나요? (예: AI협업규칙.md) 있으면 경로를, 없으면 '없음'.

6. 검토 짝꿍으로 쓸 모델은요? 비우면 제가 "지금 쓰는 모델의 한 단계 위, 맨 위면 한 단계 아래"로 고를게요.
   예) GPT-6 Astra / GPT-6.1 Sol / Claude Opus / Claude Sonnet
   이 답은 저장돼요. 나중에 "이번엔 ○○로 검토해"라고 하면 그때만 바꿔요.
```

답을 받으면 **말없이** 아래를 한다. 끝나면 무엇을 만들었는지 경로를 한 번에 보여 준다.

1. **짝꿍 종류를 정한다.** 2번 답으로 판단한다.
   - **폴더 짝꿍**: 코덱스 앱·클로드 코드·제미나이 CLI처럼 내 컴퓨터 폴더를 읽는 도구가 둘 이상. 공유 폴더로 파일을 주고받는다.
   - **손전달 짝꿍**: 한쪽이 챗GPT 웹·클로드 웹처럼 폴더를 못 읽는 도구. 사용자가 파일을 첨부해 주고, 답을 복사해 공유 폴더에 저장한다. 반장은 "이 파일을 짝꿍 창에 첨부하고, 답을 그대로 저장해 주세요"라고 매번 한 줄로 부탁한다.
   - **혼자**: AI 도구가 하나. 아래 "혼자 판"대로 다른 모델을 짝꿍으로 띄운다.
2. **공유 폴더를 만든다.** 4번에 경로가 있으면 그 안에, 없으면 지금 작업 폴더 안에 `live_collaboration` 폴더를 만든다. 이미 있으면 그대로 쓴다. 안에 `백업` 폴더도 둔다.
3. **협업 규칙 파일.** 5번이 '없음'이면 이 스킬의 `templates/협업규칙.md`를 공유 폴더 위(작업 폴더)에 `협업규칙.md`로 복사한다. 경로가 있으면 복사하지 않고 그 파일을 규칙으로 삼는다.
4. **AGENTS.md와 CLAUDE.md.** 작업 폴더에 AI가 매번 읽을 안내를 둔다. **이미 있으면 덮어쓰지 않는다.**
   - `AGENTS.md`가 있으면 `AGENTS.md.bak`으로 복사해 두고, 파일 끝에 `templates/AGENTS-블록.md`의 내용을 `<!-- duli 시작 -->`과 `<!-- duli 끝 -->` 사이에 덧붙인다. 그 표시가 이미 있으면 사이만 바꾼다(두 번 붙지 않는다). 덧붙인 줄을 사용자에게 보여 준다.
   - 없으면 블록만으로 `AGENTS.md`를 만든다.
   - `CLAUDE.md`가 없으면 `@AGENTS.md` 한 줄짜리로 만든다. 있으면 `@AGENTS.md` 줄이 없을 때만 그 줄을 덧붙인다.
   - 블록 안의 `<협업규칙 경로>`와 `<공유 폴더 경로>`는 실제 경로로 바꿔 넣는다.
5. **프로필을 저장한다.**

```json
// ~/.duli/profile.json
{ "nickname": "라이프스케줄", "tools": ["클로드 코드", "코덱스 앱"], "partner_kind": "folder", "devices": "노트북 2대, 윈도우",
  "shared_dir": "C:/Users/me/OneDrive/me/live_collaboration", "rules_file": "C:/Users/me/OneDrive/me/협업규칙.md",
  "partner_model": "GPT-6 Astra", "set_at": "2026-10-09", "skill_version": "2026-10-09.1" }
```

6. **짝꿍 프롬프트를 보여 준다.** 아래 "짝꿍 프롬프트"에 실제 경로와 이름을 넣어 코드블록으로 보여 주고, "짝꿍 AI 창에 이걸 붙여 넣어 두면 돼요"라고 한 줄만 한다. 손전달 짝꿍이면 "파일은 제가 만들 때마다 첨부 부탁드릴게요"를 덧붙인다. 혼자면 보여 주지 않는다.
7. 마지막에 한 줄: "다음부터는 `/duli`라고 치거나 '설계 검토해', '같이 해', '마무리 검토해'라고 하면 돼요."

설치 직후 사용자가 이미 할 일을 말했으면(예: "이 설계 검토해"), 설정이 끝나자마자 그 문으로 바로 들어간다.

## 매번: 시작 전 확인 (말없이)

- 오늘 날짜를 명령으로 확인한다(추정 금지).
- 프로필을 읽는다. 공유 폴더가 실제로 있는지 본다. 없으면 만들고 한 줄 알린다.
- 공유 폴더에서 같은 프로젝트의 **기존 순번**을 찾는다. 있으면 이어 쓴다.
- 새 버전 확인: 인터넷이 되면 `https://raw.githubusercontent.com/lifeschedule-dotcom/duli/main/.claude/skills/duli/VERSION`을 읽어 설치본 `VERSION`과 비교한다. 4초 안에 안 되면 조용히 넘어간다. 더 새 것이 있으면 한 번만 묻는다. "스킬에 새 버전이 있어요. 지금 받을까요?" 받으면 README의 설치 명령을 다시 실행하고 "받았어요. 이 창을 껐다 켜고 다시 /duli라고 쳐 주세요"라고 하고 멈춘다. "다음에"면 이번 대화에서 다시 묻지 않는다.

### 어느 문인지 정하기

사용자 말에서 먼저 본다. "설계·아이디어·방향·맞는지" → ①. "나눠·같이·분배·조사해 줘" → ②. "마무리·최종·더 나은·올리기 전" → ③. 말이 애매하면 공유 폴더를 본다. 설계 문서만 있고 `01 작업 분배` 파일이 없으면 ①, 합친 결과물이 있으면 ③. 그래도 모르면 **그때만** 묻는다. 선택창이 있으면 보기 셋(설계 검토 / 나눠서 하기 / 마무리 검토), 없으면 번호 목록.

## 공통 뼈대 (세 문이 같이 쓴다)

### 파일 이름

**`<프로젝트> <순번> <할 일> → <받을 AI> - YYYY-MM-DD HHMM <쓴 AI>.md`**
예: `대시보드 피드백 03 합친 글 검토 요청 → GPT - 2026-10-07 1330 Claude.md`

- 순번은 프로젝트 안에서 01부터 올라가고, 누가 쓰든 같은 번호 줄을 이어 쓴다.
- 화살표 "→"를 치기 어려우면 "to"도 같은 뜻이다: `… 03 합친 글 검토 요청 to GPT - ….md`
- 상대의 파일은 절대 고치지 않는다. 답은 새 파일로.
- 파일을 고쳐 다시 올릴 때는 이전 판을 `백업\… vN.md`로 둔다.

### 답 파일에 늘 넣는 것

**한 일 / 증거(경로·근거·출처) / 확인 못 한 것 / 판단이 갈리는 것(선택지 + 추천 + 근거)**. 사실은 **[확인] [2차] [추정] [미확인]**을 붙인다. 사용자·제3자의 감정과 의도는 추측해 쓰지 않는다.

### 폴더 지켜보기 (도구마다 다르다)

| 반장 도구 | 방법 |
|---|---|
| 클로드 코드 | 폴더 지켜보기 도구(Monitor)로 `→ Claude` 새 파일을 알리게 한다. 30분마다 다시 켠다. 폴링하지 않는다. |
| 코덱스 앱·제미나이 CLI | 2분마다 폴더를 한 번 본다. |
| 손전달 짝꿍 | 지켜보지 않는다. 사용자가 "답 저장했어요"라고 하면 읽는다. |

- 30분 넘게 답이 없으면 사용자에게 한 줄 알린다. 동기화 지연일 수 있다. 다른 컴퓨터의 짝꿍이면 "파일이 그쪽 폴더에 보이는지" 확인을 부탁한다.
- 짝꿍이 폴더를 못 찾을 때는 **전체 경로를 그대로** 적어 준다. 이름에 화살표와 가운뎃점이 있어 검색으로는 못 찾는 경우가 있다.

### 짝꿍 프롬프트 (01 파일 맨 아래에도 붙인다)

```
이 프로젝트의 반장은 <반장 AI>이고, 너는 짝꿍이야.
- 공유 폴더: <공유 폴더 전체 경로>. 2분마다 확인해서 너에게 온(→ <너>) 새 MD 파일을 읽고 일해 줘.
- 답은 같은 이름 규칙의 새 MD 파일로: <프로젝트> <순번> <할 일> → <받을 AI> - 날짜 시간 <너>.md
- 상대의 원본은 고치지 마. 답에는 한 일 / 증거 / 확인 못 한 것 / 판단이 갈리는 것(선택지+추천+근거)을 적어 줘.
- 검토를 요청받으면 반장의 의견을 읽기 전에 결과물부터 먼저 읽고 네 판단을 적어. 그다음 "틀린 것"과 "실제로 안 통할 수 있는 것"을 근거와 함께 적고, 없으면 "더 고칠 거 없음"이라고 분명히 써 줘.
- 사실은 [확인/2차/추정/미확인]을 구분해. 의견이 갈리면 사용자에게 묻지 말고 의견 맞추기 파일에서 근거로 끝내. 새 근거가 없으면 "새 근거 없음"이라고 써.
- 게시·발송·삭제·배포는 하지 마. 그건 사용자가 해.
- "완료" 파일이 오면 폴더 확인을 멈춰 줘.
```

### 혼자 판 (AI 도구가 하나일 때)

짝꿍 자리에 **다른 모델을 새로 띄운 하위 작업자**를 쓴다. 같은 대화 안에서 역할만 바꾸면 반장의 생각을 이미 다 본 상태라 독립 검토가 안 된다. 새로 띄운 작업자는 대화를 모르고 파일만 읽으니 "먼저 혼자 읽기"가 저절로 된다.

- **모델은 사용자가 정한다.** 프로필의 `partner_model`을 쓴다. 사용자가 이번 회차에 "이번엔 ○○로 검토해"라고 하면 그때만 그 모델로 바꾸고 프로필은 그대로 둔다. 비어 있으면 아래 추천 규칙으로 반장이 고르고, 어떤 모델을 골랐는지 첫 알림 한 줄에 적는다.
- **추천 규칙 한 줄: 지금 쓰는 모델의 한 단계 위, 이미 맨 위면 한 단계 아래.** 모델 사다리는 바뀌니 이름을 외우지 말고, 지금 도구가 보여 주는 모델 목록(`/model`)에서 고른다. 못 띄우면(요금제에 없음) 한 단계 아래로 내려가고, 어떤 모델이 검토했는지 완료 파일에 적는다. 다른 모델을 하나도 못 고르면 "다른 모델 없음, 반장 스스로 검토"로 표시하고 하위 작업자를 띄우지 않는다.
- 2026-10-09 기준 예시. 클로드: Haiku → Sonnet → Opus → Fable(맨 위면 Opus). 코덱스: Luna → Sol → Astra(Astra가 맨 위면 짝꿍은 Sol). 추론 강도(앱에서는 Light·High·Extra High, 설정 파일에서는 low·medium·high·xhigh)는 같은 모델일 때만 한 단계 올린다.
- **독립성 사다리.** 위 단계가 안 되면 아래로 내려가되, 어느 단계였는지 완료 파일에 적는다.
  1. 다른 회사 AI (클로드 ↔ GPT)
  2. 같은 도구의 다른 모델을 새로 띄움 (Sonnet ↔ Opus, Sol ↔ Luna). 챗GPT 웹만 쓰면 **다른 모델로 새 대화창**을 열어 손전달로 한다.
  3. 같은 모델, 새 대화창. 대화를 모르니 "먼저 혼자 읽기"는 된다.
  4. 반장 스스로 검토. "검토 안 됨"으로 적는다.
- 하위 작업자에게는 **파일 경로와 질문만** 준다. 답은 똑같이 `… → <반장> - 날짜 <모델 이름>.md`로 공유 폴더에 저장하게 한다. AI 둘일 때와 기록 모양이 같아진다.
- 회차마다 하위 작업자 1번, 최대 2회차. 세 번째부터는 반장이 스스로 검토로 닫는다.

## ① 설계 검토 (아이디어가 완성되기 전)

> 사용자에게: "설계안을 파일로 정리하고 짝꿍에게 먼저 읽게 할게요."

1. 반장이 지금까지 대화에서 나온 설계를 **설계안 파일 하나**로 정리한다. 목표 한 줄, 하기로 한 것, 안 하기로 한 것, 전제(사실로 믿고 있는 것), 열린 질문. 공유 폴더에 `<프로젝트> 01 설계안 v1 → <짝꿍> - ….md`로 올린다. 반장의 평가·장점 설명은 넣지 않는다. 짝꿍이 끌려간다.
2. 01 파일에서 묻는 것: **틀린 전제 / 빠진 경우 / 더 단순한 대안 / 이 설계가 실패하는 조건**. 답 형식은 "채택 / 더 나은 대안+근거 / 틀림+근거". 끝에 "더 고칠 거 없음" 여부를 분명히.
3. 짝꿍 답이 오면 반장이 항목마다 정한다: **반영 / 반영 안 함(이유) / 토론으로**. 반영한 것은 설계안 v2로 고치고(이전 판은 백업), 반영표와 함께 `03 설계안 v2 재검토 요청`을 올린다.
4. 끝 조건: 반장의 스스로 검토와 짝꿍 답이 **둘 다 "더 고칠 거 없음"**. 그러면 `설계 확정본`으로 저장하고 닫기로 간다. 사용자에게 "설계가 확정됐어요. 이대로 나눠서 할까요?"라고 ②를 한 줄 권한다.

## ② 나눠서 하기

> 사용자에게: "일을 나눠서 짝꿍에게 보낼게요."

1. 반장이 `<프로젝트> NN 작업 분배 → <짝꿍>` 파일을 올린다. 상대가 따로 설명 없이 바로 일할 수 있게 **배경·목표·현재 상태·완료 기준·결과물 저장 위치·지키는 것**을 다 적는다. 설계 확정본이 있으면 경로를 적는다. 맨 아래에 짝꿍 프롬프트를 붙인다.
2. 나눌 때 기준: **사실 조사·대안 비교·다른 시각 검토는 짝꿍에게, 합치기·최종 판단·기록은 반장이.** 자기 몫은 바로 한다.
3. 짝꿍 답이 돌아오면 반장이 **최종본 하나**로 합친다. 합치기 전 원본은 `백업\`에 둔다. 조각 상태로 끝내지 않는다.
4. 합치면 바로 ③으로 간다.

## ③ 마무리 검토 (결과물이 나온 뒤)

> 사용자에게: "결과물을 짝꿍에게 먼저 읽게 하고 있어요."

1. **반장이 스스로 검토를 먼저 한다.** 기준은 둘: 틀린 것, 실제로 안 통할 수 있는 것. 처방마다 "이게 실패하는 상황은?"을 한 줄씩 생각하고, 답이 있으면 본문에 조건을 붙인다. 고친 목록을 표로 남긴다. 이 표는 짝꿍에게 보내는 파일의 **맨 아래**에 둔다. 짝꿍이 결과물을 먼저 읽게 하기 위해서다.
2. `<프로젝트> NN 검토 요청 → <짝꿍>` 파일을 올린다. 묻는 것을 번호로: **틀린 것 / 실제로 안 통할 것 / 더 나은 방향 / 공개 전 개인정보·비밀값**. 답 형식은 "채택 / 더 나은 대안+근거 / 틀림+근거", 바꿀 문장은 직접 제안하게 한다. 없으면 "더 고칠 거 없음"을 분명히.
3. 짝꿍 답이 오면 **지적마다 상태를 표로** 정한다.

| 짝꿍 지적 | 상태 | 이유 |
|---|---|---|
| … | 채택 / 반박(근거) / 보류(사용자만 아는 사실) / 토론으로 | … |

   "짝꿍이 동의했다"는 사실 확인이 아니다. 숫자·기능·정의는 출처로 확인한다.
4. 채택이 하나라도 있으면 고치고, 판을 올리고(v2→v3), 반영표와 함께 재검토를 요청한다. 순번 +1.
5. **끝 조건:** 반장의 스스로 검토와 짝꿍의 답이 **둘 다 "더 고칠 거 없음"**인 회차가 한 번 나오면 끝. 오타·표현 수준만 남으면 반장이 반영하고 끝 조건으로 본다.

### 의견이 갈릴 때 — 사용자에게 묻지 말고 토론으로 끝낸다

같은 지적이 두 회차 연속 나오면 **의견 맞추기 파일**을 연다. `<프로젝트> NN 토론: <쟁점> → <짝꿍>`. 쟁점 한 줄, 양쪽 주장, 각 주장이 **틀리는 조건**, 확인할 수 있는 출처·시험 방법. 짝꿍은 같은 형식으로 답하고, 새 근거가 없으면 "새 근거 없음, 상대 안 채택"이라고 쓴다.

- 반장이 결정하고 이유를 적는다. 기준: 출처로 확인되는 쪽 → 실패 조건이 더 적은 쪽 → 사용자가 바로 쓸 수 있는 쪽. 결정 뒤에는 같은 쟁점을 다시 열지 않는다.
- 쟁점당 2왕복까지. 그래도 안 갈리면 **둘 다 적되 조건을 붙여** 넣는다("A가 맞는 경우: … / B가 맞는 경우: …").
- 사용자에게는 결과만 알린다. 사업·취향·비용처럼 **사용자만 아는 사실**이 열쇠일 때만 질문 하나를 남기고, 그동안은 기본값을 정해 진행한다.

### 검토가 실패하면 실패라고 쓴다

짝꿍이 답을 안 보냈거나, 파일을 못 읽었거나, 다른 모델을 못 띄웠으면 그 회차는 **"검토 안 됨"**이다. 반장이 스스로 검토한 것을 "교차검토 통과"라고 쓰지 않는다. 완료 파일에 어느 회차가 누구의 검토였는지 적는다.

## 닫기 (반장)

1. `<프로젝트> NN 완료 → <짝꿍> - … <반장>.md`를 올린다. 내용: 반영한 것 / 반영하지 않은 것과 이유 / 토론 결정과 이유 / 어느 모델·AI가 검토했는지 / 최종 결과물 전체 경로 / **"추가 검토 필요 없음, 폴더 확인을 멈춰도 됨"**.
2. 짝꿍은 완료 파일을 읽으면 폴더 확인을 멈춘다. 반장도 폴더 지켜보기를 멈춘다.
3. 작업 기록 파일이 있는 프로젝트면(옵시디언 상세기록 등) 기록 한 줄을 남긴다. 없으면 완료 파일이 기록이다.
4. 사용자에게: **바뀐 것 3줄 이내 + 토론으로 정한 것(있으면 한 줄씩) + 결과물 경로.** 답장 내용을 다시 나열하지 않는다. 게시·배포 여부는 사용자가 정한다.

## 요청할 때만

- **"프로필 다시 설정"**: 처음 1회 설정을 다시.
- **"스킬 업데이트해 줘"**: 새 버전 확인과 같은 명령. 최신이면 "지금이 최신이에요(버전)"라고만.
- **"지금 어디까지 왔어?"**: 공유 폴더의 이 프로젝트 파일 목록과 마지막 상태(누구 차례인지)를 다섯 줄 안에.
- **"짝꿍 프롬프트 다시 줘"**: 실제 경로를 넣은 짝꿍 프롬프트를 코드블록으로.

## 절대 하지 않는 것

- 게시·발송·삭제·배포. 완료 파일까지가 이 스킬의 끝이다.
- 상대 AI의 파일을 고치는 것. 답은 새 파일로.
- 비밀값·개인정보·대화 전체를 파일에 넣는 것.
- 사용자·제3자의 감정과 의도를 추측해 적는 것.
- "상대가 동의했다"를 사실 확인으로 치는 것. 숫자·기능·정의는 출처로.
- 검토가 안 된 회차를 통과로 쓰는 것.
- 반장 의견을 결과물보다 앞에 두어 짝꿍이 끌려가게 하는 것.
- 사용자에게 의견 차이를 떠넘기는 것. 토론 파일로 끝낸다.
